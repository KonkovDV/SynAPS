# T-06. Звуковая релаксация мастера LBBD

> Код: `synaps/solvers/_lbbd_sound.py`; включение: `LbbdSolver.solve(..., sound_cuts=True)`.
> Тесты: `tests/test_lbbd_sound_cuts.py` (оракул полного перебора
> `tests/_fjsp_oracle.py`), `tests/test_public_instances_bks.py`.
> Evidence: `benchmark/evidence/lbbd-sound-cuts-2026-10-25/`.
> План: `docs/rfc/AI_EXECUTOR_PLAN_2026_10.md`, T-06.

## 1. Почему не «дисконтирующие» отсечения

После S1/S2/S3 и KI-S3 в мастере LBBD остались только no-good. Отсечения
вида `C ≥ L(S) − Σ_{j ∈ S, ушла с машины} Δ_j` требуют, чтобы величина
`L(S) − L(S \ {j})` была ограничена известным `Δ_j`. Для BHK по сырой
матрице переналадок это неверно (GUARD-S3), поэтому такие отсечения убраны.

Здесь используется другой класс строк: **допустимые неравенства** исходной
задачи. Каждая строка выполняется на **любом** допустимом расписании при его
собственном назначении. Мастер «назначения + любые такие строки» остаётся
релаксацией задачи, его доказанная двойственная оценка — нижняя оценка
makespan. Это верно независимо от того, на каком инкумбенте строку нашли.
Поэтому отделять строки можно лениво, на каждом решении мастера.

No-good по-прежнему не является допустимым неравенством: подзадача LBBD
решается по кластерам и пересобирается, её makespan — верхняя оценка для
назначения. Поэтому отчётная оценка берётся только из мастеров без no-good:
первого мастера (в нём no-good ещё нет) и финального пересчёта по всему пулу
звуковых строк (`compute_sound_master_lower_bound`). Используется максимум
этих двух значений.

## 2. Модель и обозначения

Оценка относится к модели целочисленной сетки резервирования, общей для всех
солверов (P0-4), — так же, как прежний мастер и `lower_bounds.py`.

* `p_jk = duration_minutes_for(j, k)` (T-30 overrides учитываются),
  `L_k = max_parallel`.
* `r_j` — CEIL-смещение `max(release, earliest_start, 0)`
  (`operation_earliest_offset_minutes`), как в CP-SAT.
* Голова `h_j = max(r_j, h_g + min_k p_gk)`, где `g` — предшественник по
  цепочке. Хвост `t_j = max_{s — преемник} (min_k p_sk + t_s)`.
* `s_k(a, b)` — переналадка на машине `k`. Отсутствующая ячейка равна 0, как в
  солверах. На первой операции машины переналадки нет: в CP-SAT дуги из депо
  её не несут.
* `C` — makespan мастера, `y_jk` — назначение,
  `z_kx ∈ [0, 1]`, `z_kx ≥ y_jk` для операций `j` состояния `x`, допустимых
  на `k`.

Свойства любого допустимого расписания `σ` (с makespan `C_σ`):

* **(H)** `start_j ≥ h_j`: релиз и окно ограничивают старт, предшественник
  заканчивается не раньше `h_g + p_g(σ) ≥ h_g + min p_g`; индукция по
  цепочке.
* **(T)** `C_σ ≥ end_j + t_j`: цепочка преемников исполняется
  последовательно после `j`, каждое звено не короче минимальной
  длительности.
* **(D)** На однодорожечной машине для соседних по порядку `a → b`:
  `start_b ≥ end_a + s_k(a, b)`. На машине с `L` ручьями в каждый момент
  исполняется не более `L` операций.

Календари, вспомогательные ресурсы, `latest_finish` и обобщённые
`precedence_edges` только сужают множество расписаний. Строки на них не
опираются и остаются валидными. Режимы (`modes`) вне области: LBBD их
отвергает.

## 3. Семейства строк и доказательства

### 3.1 `chain` (статические)

Для пути `P` от операции `i` до листа цепочки:
`C ≥ h_i + Σ_{j ∈ P} Σ_k p_jk y_jk`.

*Доказательство.* По (H) `start_i ≥ h_i`. Операции пути идут
последовательно, каждая длится `p_j(σ)`. Последняя заканчивается не позже
`C_σ`. ∎

Строка добавляется для корня и для операций, у которых собственный релиз
больше `h_g + min p_g`. Иначе её доминирует строка предшественника.

### 3.2 `energy` (ленивые, с якорем)

Для машины `k` и порогов `(r, q)`, **заякоренных** операцией `i`
(`h_i ≥ r`, `t_i ≥ q`, машина `i` любая):

`C ≥ r + q − f_k + Σ_{j: h_j ≥ r, t_j ≥ q} (p_jk / L_k + f_k) y_jk`.

Здесь `f_k` — порог переходов `compute_machine_transition_floor` (только для
однодорожечной машины, иначе 0).

*Доказательство.* Пусть `A` — операции множества, назначенные в `σ` на `k`.
Если `A = ∅`, по (H), (T) для якоря `C_σ ≥ h_i + p_i + t_i ≥ r + q ≥ r + q − f_k`.
Иначе по (H), (T) все операции `A` лежат в окне `[r, C_σ − q]`. По (D) их
суммарная обработка не больше `L_k (C_σ − q − r)`. На однодорожечной машине
между соседними по порядку операциями `A` есть хотя бы один переход, каждый
`≥ f_k` по определению порога. Значит
`Σ_A p + (|A| − 1) f_k ≤ C_σ − q − r`. ∎

*Якорь обязателен.* Без него пустое множество давало бы `C ≥ r + q`.
Прототип без якоря выдал на Brandimarte `mk02` оценку 31 при BKS 26 (а
также 64 > 57 на `mk06` и 204 > 197 на `mk10`). Пример из трёх операций с
оптимумом 11, где незаякоренная пара даёт 20, закреплён тестом
`test_energy_rows_require_an_anchor`.

Отделение: для машины и назначенных на неё операций перебираются пороги
`r` из голов, накопление идёт по убыванию хвоста, `O(n²)`. Добавляется самая
нарушенная строка.

### 3.3 `setup_in` / `setup_out` (статические, однодорожечные машины)

`in_kx = min_{v ∈ V_k, v ≠ x} s_k(v, x)`, `out_kx = min_{v ≠ x} s_k(x, v)`,
`V_k` — состояния операций, допустимых на `k`:

`C ≥ Σ_j p_jk y_jk + Σ_x in_kx z_kx − max_x in_kx` (аналогично для `out`).

*Доказательство.* Возьмём `z` = индикатор «состояние используется на `k`»
(допустимо: `z ≥ y`). Пусть `Z` — использованные состояния. Первое вхождение
каждого `x ∈ Z`, кроме состояния первой операции, следует сразу за
операцией другого состояния `v ∈ V_k`. Эти дуги различны и стоят
`≥ in_kx`. Время занятости машины `≥ Σ p + Σ` переналадок (D), старт `≥ 0`.
Для `out` рассуждение симметрично: берётся последний выход из каждого
состояния, кроме последнего. ∎

### 3.4 `state_path` (ленивые, однодорожечные машины)

`d_k` — метрическое замыкание (Флойд–Уоршелл) `s_k` на **всём** `V_k`.
`HP_k(X)` — кратчайший гамильтонов путь по `X` в `d_k` (BHK, `|X| ≤ 12`).
`ins_kx = min(max_u d_k(u, x), max_u d_k(x, u))`.

`C ≥ Σ_j p_jk y_jk + HP_k(X) − Σ_{x ∈ X} ins_kx (1 − z_kx)`.

*Лемма 1 (обход).* Обход машины по исходной матрице, посещающий все
состояния `Z ⊆ V_k`, стоит не меньше `HP_k(Z)`. Между соседними первыми
посещениями обход проходит путь в графе на `V_k`, его стоимость не меньше
`d_k`. Отрезки не пересекаются, стоимости неотрицательны.

*Лемма 2 (монотонность).* На метрической `d_k` при `Y ⊆ Z` выполнено
`HP(Y) ≤ HP(Z)`. Удаление вершины `x` между `a` и `b` заменяет
`d(a, x) + d(x, b)` на `d(a, b) ≤ d(a, x) + d(x, b)`. Удаление конца
убирает одну дугу `≥ 0`.

*Лемма 3 (вставка).* `HP(Y ∪ {x}) ≤ HP(Y) + ins_kx`: `x` дописывается в
конец (дуга `≤ max_u d(u, x)`) или в начало (`≤ max_u d(x, u)`).

*Доказательство строки.* При фактическом `Z` выполнено
`HP(Z) ≥ HP(X ∩ Z) ≥ HP(X) − Σ_{x ∈ X \ Z} ins_kx` (леммы 2, 3). Обход по
лемме 1 стоит `≥ HP(Z)`. При `Z = ∅` правая часть `≤ 0`, потому что
`HP(X) ≤ Σ ins` по лемме 3. ∎

Отличие от KI-S3. Там BHK считался на сыром индуцированном подграфе (не
монотонен) и дисконтировался на `p_j`. Здесь замыкание берётся на всём
`V_k`, монотонность доказана, а стоимость удаления ограничена `ins_kx`.

### 3.5 Следствие

Любой мастер «назначения + `capacity` + любое подмножество строк 3.1–3.4»
имеет оптимум `≤ OPT`: для оптимального расписания с `z` = индикатором все
строки выполнены. `mip_dual_bound` HiGHS — нижняя граница оптимума такой
модели, даже при остановке по времени. Каждый раунд отделения только
добавляет валидные строки, поэтому валиден и максимум оценок по раундам.

Многодорожечные машины получают только строки мощности и `energy` без
переналадок. CP-SAT разбивает их на ручьи с переналадками внутри ручья
(`_virtualize_parallel_work_centers`). Строки, не учитывающие переналадки,
валидны при любой семантике переналадок на ручьях.

## 5. Дефект, найденный оракулом: виртуальные ручьи и `machine_duration_overrides`

Сверка оракула с CP-SAT упала на первой сотне примеров с `ValidationError`.
И greedy, и CP-SAT разбивают машину с `max_parallel > 1` на виртуальные
ручьи. Обе копии переносили на ручьи `eligible_wc_ids`, но оставляли
`machine_duration_overrides` с ключом исходной машины. Преобразованная задача
не проходила валидацию модели, и **любое** решение такой задачи (GREED,
CP-SAT через тёплый старт greedy) падало исключением. Исправлено общим
помощником `synaps/solvers/_virtual_lanes.py::operation_on_lanes`: ручей
наследует override своей машины. Регрессия —
`tests/test_virtual_lane_overrides.py` (4 теста падали до исправления).

## 7. Включение и ограничения

* `sound_cuts=True` (по умолчанию выключено; golden без изменений);
  `sound_cut_rounds` (по умолчанию 8) — число раундов отделения на одно
  решение мастера; `sound_mip_rel_gap` (по умолчанию 0.02) — допуск MIP
  звуковых мастеров. Оценка первого мастера и финального мастера без
  no-good затем дожимается на штатном допуске HiGHS (1e-4) в остатке
  бюджета: на `mk07` без этого получалось 138 при 139 у прежнего мастера.
* Финальный пересчёт без no-good идёт только при остатке бюджета ≥ 1 с и не
  выходит за `time_limit_s`.
* `z`-столбцы и связи `z ≥ y` усложняют MIP мастера. На
  `medium_stress_20x4` за 30 с HiGHS не закрывает дерево. Отчётная оценка
  остаётся валидной (двойственная), но слабее предела релаксации.
* LBBD-HD не подключён: у его мастера есть временные переменные с
  предшествованием, строки `energy` / `setup_*` к нему применимы так же, это
  следующий шаг.
